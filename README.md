# Cold Email Bot

A Python-based cold outreach automation system that sends personalized emails and automated follow-ups through Outlook using the Microsoft Graph API. Built to solve a real problem during my MBA internship search, iterated based on actual usage, and currently running in production.

## Results

- 500+ emails sent across 5 weekly batches
- 20%+ genuine reply rate (industry average for cold email is 1-5%)
- 10% converted to real conversations including 1-on-1s with founders and CEOs
- Time per email reduced from 10-15 minutes manually to under 2 minutes end to end
- 100% follow-up accuracy - zero contacts missed or double-contacted
- Built and production-ready in 2 days

## The Problem

During my MBA internship search I was sending cold emails manually. The process was slow, inconsistent, and impossible to run at the scale a competitive job search requires. I had to remember who I emailed, when to follow up, whether someone replied, and I was losing track of conversations across dozens of contacts every week.

Existing tools like Mailchimp or Outreach.io are built for marketing teams running bulk campaigns. They send emails that look automated, cost hundreds of dollars a month, do not integrate naturally with a personal Outlook account, and strip away the personal feel that makes cold outreach actually work. I needed something that felt like I typed every email myself, tracked the full pipeline in a format I could control, and ran without constant manual intervention.

## The Solution

A lightweight Python automation system that:

- Sends each email individually through my actual Outlook account via Microsoft Graph API so every email arrives as a personal send, not a bulk campaign
- Schedules batches of emails at a specific date and time with randomized 1-3 minute gaps between sends to mimic human behavior and stay out of spam filters
- Follows up automatically every 3 days as a reply in the same thread, so the recipient sees one continuous conversation rather than disconnected emails
- Detects replies by matching conversation IDs, not just sender email addresses, which eliminates false positives and ensures no one receives a follow-up after they have already responded
- Tracks the full pipeline in a simple Excel file with three tabs: Active Outreach, Replied, and Archived
- Imports contact batches generated by AI in one command, removing manual data entry entirely

## Target User

**The Active Job Seeker running a structured search**

Someone who is reaching out to 50-200 companies simultaneously, needs every email to feel individually written, has no budget for enterprise sales tools, and is losing hours every week to manual follow-up tracking that could be automated.

The key insight behind this persona: most job search advice tells you to personalize every email, which is right, but no one tells you how to do that at scale without it consuming your entire week. This tool solves exactly that gap. Personalization happens at the writing stage with AI assistance. Everything after that is fully automated.

What I got wrong initially: I assumed the hardest part would be sending emails. The actual hardest part was reply detection. My first version matched by sender email address, which broke immediately when someone replied from a different address than expected, or when an old reply from before the outreach campaign triggered a false positive. Switching to conversation ID matching fixed this completely.

## How AI Is Integrated

AI is used at three distinct layers in this workflow:

**1. Content generation**

I use Claude to write personalized cold email bodies and follow-up messages for each contact. The input is the company name, contact name, role, and a one or two line observation about what caught my attention about the company. Claude returns a plain text email body formatted exactly for this system: asterisks for bullet points, blank lines between paragraphs, no markdown, no em dashes, signed off consistently.

The key design decision here was deliberate: I kept a human review layer between Claude and the send button. Every email Claude writes, I read before it goes out. This keeps the emails genuinely personalized rather than formulaic, and it means I catch anything that does not sound right before it reaches someone's inbox.

**2. Contact list generation**

Instead of manually filling out spreadsheet rows, I ask Claude to generate a full batch of contacts in the exact column format this system expects. I save the output as a file and run one import command. What used to take 30 minutes of copy-pasting now takes 2 minutes.

**3. System design and development**

I used Claude as a development partner to build this entire system. This included debugging Microsoft Graph API authentication issues specific to a university-managed Azure tenant, designing the reply detection logic using conversation IDs, working through scheduled send API behavior where emails are queued as drafts before delivery, and iterating on HTML email formatting to match Outlook's native rendering across clients.

The distinction I want to draw: AI did not generate this project. I defined the problem, scoped the solution, made every architecture decision, and discovered the real requirements by using the system in production. AI accelerated execution across a domain I was learning from scratch and helped me work through specific technical problems in real time.

## What I Learned

**The real requirements only appeared after shipping.**

My initial build covered the obvious flows: send email, wait, follow up. What I did not anticipate was everything that breaks at the edges. Follow-up emails were threading back to my own inbox instead of the recipient. Scheduled emails were landing an hour off because of daylight saving time transitions. The Excel import was failing silently because Claude put a title row above the headers. Reply detection was triggering on emails that arrived before the outreach even started.

Every one of these was a real production bug I found by actually using the system, not by reviewing the code.

**The tradeoffs I made consciously:**

Excel over a database: a database would be more robust, but Excel means I can open the file, see everything, and manually intervene in seconds. For a solo operator that flexibility matters more than scalability.

Personal Outlook over a marketing platform: deliverability and trust. An email from my wisc.edu account in a real thread performs better than anything sent through a third-party platform.

Human review over full automation: I deliberately did not connect the AI directly to the send pipeline. The emails perform better when I read them before they go out, and I can tell immediately when something does not sound like me.

**What I would build next:**

A lightweight dashboard to visualize reply rates by company type, industry, and follow-up number, so I can see which outreach is working and double down on it. The data is already in Excel but it needs to be surfaced visually to be useful. I would also add a mobile-friendly web interface so the daily check does not require opening a terminal.

## Tech Stack

- Python 3.9+
- Microsoft Graph API with OAuth2 device code flow
- MSAL for authentication and token refresh
- openpyxl for Excel read and write
- Outlook scheduled send for time-based delivery

## Setup

### 1. Clone the repo

```bash
git clone https://github.com/YOUR_USERNAME/cold-email-bot.git
cd cold-email-bot
```

### 2. Install dependencies

```bash
pip3 install msal openpyxl requests
```

### 3. Register an Azure app

1. Go to [portal.azure.com](https://portal.azure.com)
2. Microsoft Entra ID → App registrations → New registration
3. Name: cold-email-bot, Supported account types: Multitenant
4. Add delegated permissions: Mail.Send, Mail.ReadWrite
5. Certificates and secrets → New client secret → copy the value
6. Authentication → Allow public client flows → Yes

### 4. Configure credentials

```bash
cp config.ini.template config.ini
```

Fill in your values in `config.ini`. This file is in `.gitignore` and will never be committed.

### 5. Set up Excel tracker

```bash
cp outreach.template.xlsx outreach.xlsx
cp latestList.template.xlsx latestList.xlsx
```

### 6. Run

```bash
cd src
python3 main.py
```

On first run you will be prompted to log in via a device code. After that the token refreshes automatically.

## CLI Options

```
1.  Send new emails       - sends all Pending contacts immediately with random delays
1b. Schedule sends        - schedule all Pending emails from a specific date and time
2.  Run daily check       - scans inbox for replies, then sends due follow-ups
3.  Status summary        - shows pipeline counts and follow-ups due today
4.  Fix email address     - correct a wrong email and reset that contact to Pending
5.  Import contacts       - imports from latestList.xlsx into Active Outreach
6.  Exit
```

## Workflow

### Generating and importing contacts

Ask Claude or any LLM to generate a contact list using this format prompt:

```
Generate an Excel file with these exact columns:
Company | Contact Name | Email | Subject | Initial Email Body | Follow-up Body | Status

Rules:
- Status: always Pending
- Date Sent, Follow-up Count, Last Follow-up Date: leave empty
- Plain text only in email bodies
- Use * for bullet points
- Blank line between paragraphs
- Single line breaks within a block
- No em dashes
- Signature always:
  Best Regards,
  [Your Name]
  [Your Title]
```

Save the file as `latestList.xlsx` in the root folder and run Option 5.

### Scheduling sends

```
Select option: 1b
Enter start date and time (YYYY-MM-DD HH:MM): 2026-06-01 09:00
```

Emails go out with 1 to 3 minute random gaps. 100 emails take roughly 3 hours. Outlook delivers them automatically with no need to keep your computer on.

### Daily check

Run Option 2 each morning. It scans your inbox for replies first, moves them to the Replied tab, then sends any follow-ups that are due.

```ini
log_path                 = outreach.log
token_cache_path         = token_cache.json
import_path              = latestList.xlsx
follow_up_interval_days  = 3
max_follow_ups           = 5
min_delay_seconds        = 30
max_delay_seconds        = 60
schedule_min_gap_seconds = 60
schedule_max_gap_seconds = 180
```

## Security

- config.ini and token_cache.json are in .gitignore and never committed
- OAuth2 device code flow - no password stored anywhere
- Refresh tokens expire after 90 days of inactivity; re-login takes 30 seconds
